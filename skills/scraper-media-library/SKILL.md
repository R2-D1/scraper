# Scraper media library

Використовуй цей скіл як єдину точку входу для роботи з медіабібліотекою scraper. Не шукай методологію у випадкових документах проєкту: прочитай лише спільні правила та матеріал потрібного режиму.

## Маршрути

1. Завжди прочитай [спільні правила](references/shared-rules.md).
2. Для завантажених фото Unsplash прочитай [Unsplash](references/unsplash.md) і [переклади зображень](references/image-translations.md).
3. Для Lummi-фото прочитай [Lummi](references/lummi.md) і [переклади зображень](references/image-translations.md).
4. Для Pexels-фото прочитай [Pexels](references/pexels.md) і [переклади зображень](references/image-translations.md): вручну описуй зображення англійською, а відсутні українські переклади отримуй через налаштований DeepL API.
5. Для Pexels-відео прочитай [Pexels video](references/pexels-videos.md) і [переклади зображень](references/image-translations.md): переглядай саме відео, а poster використовуй лише для навігації.
6. Для власних згенерованих зображень прочитай [власні зображення](references/custom-images.md). Правила перекладів уже включені в цей режим; Unsplash API до нього не належить.
7. Для Iconify прочитай [іконки](references/iconify.md) і [переклади іконок](references/icon-translations.md).
8. Для CtrlV SVG-ілюстрацій прочитай [CtrlV](references/ctrlv.md) і [переклади зображень](references/image-translations.md).
9. Для unDraw SVG-ілюстрацій прочитай [unDraw](references/undraw.md) і [переклади зображень](references/image-translations.md).
10. Для планування, перевірки стану або запуску синхронізації будь-якого медіа прочитай [синхронізацію середовищ](references/sync.md).

Не завантажуй матеріали інших режимів без потреби.

## Дозволи

- Аудит стану та inventory є read-only.
- Будь-який локальний етап, який записує або видаляє intake, бібліотеку, черги чи словники, потребує явного дозволу користувача. Явна команда виконати конкретний локальний цикл є таким дозволом.
- Підготовка архіву не є серверним імпортом і потребує окремого дозволу, якщо не була прямо включена в запит.
- Dev, Stage і Production є трьома окремими змінами зовнішнього стану. Не вважай дозвіл на одне середовище дозволом на інше.
- Не називай успішне пакування, передачу файлу або постановку в чергу завершеною серверною синхронізацією.

## Інваріант підготовлених зображень

- Для звичайного пакування й синхронізації запускай лише канонічні `pnpm run media:*` команди. Не викликай внутрішні TypeScript-скрипти напряму.
- Звичайна підготовка зберігає вже оптимізовані файли, оновлює їхні метадані та створює лише відсутні результати. Вона не повинна повторно обрізати або оптимізувати готову бібліотеку.
- Для растру кожен цільовий розмір генеруй прямо з оригіналу й кодуй у WebP один раз. Не створюй responsive-варіанти з уже стисненого основного WebP; основний WebP обмежуй найбільшою налаштованою шириною варіанта.
- Повна raster-переоптимізація з файлами створює raster-only план: примусово перезаписує raster-assets і не додає SVG чи відео.
- Зберігай стандартний формат і чинні обмеження пайплайна. SVG понад ліміт лишай у бібліотеці без запису в черзі синхронізації. Інші помилки обробки (наприклад, коли WebP encoder відхиляє розмір) лишай помилками/необробленими файлами; не додавай fallback в інший формат, зміну розміру чи інший обхід без прямого запиту користувача.
- `--clean` означає повну регенерацію всіх підготовлених зображень. Використовуй його лише після окремого прямого запиту користувача на повну регенерацію, наприклад через зміну параметрів оптимізації. Дозвіл на повний sync, export, пакування або конкретне середовище не дозволяє `--clean`.
- Sync середовища ніколи не повинен сам очищати теку підготовлених зображень. Якщо готового файла бракує, дороби лише його; якщо потрібно змінити лише метадані, не торкайся бінарного файла.

## Звіт

Розділяй локально прийняті файли, переклади, колекції, підготовлений архів і фактичний результат кожного середовища. Не перекладай роботу з чергами перекладів на користувача, якщо локальний цикл уже дозволений.
