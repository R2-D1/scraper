# Unsplash

## Вхід і межі

- Вхідна тека: `intake/unsplash/`, вона не версіонується.
- Назва файла: `<slug>-unsplash.<ext>`. Не перейменовуй файл до імпорту.
- Звичайна нова пачка не використовує повне стягування бібліотеки: воно може видалити локальні записи, яких немає у списках URL.
- Локальний імпорт після успіху прибирає прийнятий файл з intake, тому спочатку потрібен явний дозвіл на локальний цикл.

## Blacklist авторів

- Заборонених авторів зберігай у `library/unsplash-author-blacklist.json` як Unsplash usernames без `@`.
- Перед збереженням metadata перевіряй username та URL профілю. Заблоковане фото тихо пропускай без помилки й не додавай до бібліотеки.
- Після зміни blacklist запусти `pnpm run unsplash:apply-author-blacklist`. Команда видалить уже імпортовані фото цих авторів локально, додасть їхні media keys до списку серверного видалення та почистить пов'язані групи.
- Після цього окремо запускай дозволену синхронізацію, щоб застосувати видалення на сервері. Повторне додавання URL заблокованого автора безпечне: імпорт знову тихо його пропустить.

## Локальний цикл автоматичного імпорту

Для raster-пачки використовуй один запуск `pnpm run unsplash:import-downloads -- --keep --raster-only`. Імпорт читає локальні sidecar JSON з intake, а після перенесення автоматично запускає DeepL для відсутніх українських name, alt і tags. Українські черги вручну не заповнюй.

1. Перевір кількість, формат назв, підтримувані розширення та дублікати в intake.
2. Запусти `pnpm run unsplash:import-downloads`. Команда визначає запис з імені файла, отримує метадані через Unsplash NAPI з офіційним API fallback, переносить asset у `library/unsplash`, створює `media-meta.json`, оновлює URL-список і missing-черги.
3. Для нових черг виконай правила з [перекладів зображень](image-translations.md). Самостійно заповни їх, запусти `pnpm run images:promote-missing`, а потім для кожного нового slug — `pnpm run images:update-translations -- --slug <slug>`.
4. Прочитай актуальний реєстр колекцій, переглянь кожен asset і запиши мінімально достатні `collectionSlugs` за спільними правилами. Не класифікуй пачку за словами зі slug/назв/тегів. Asset без прямої відповідності залиш невирішеним і не пакуй замість примусового призначення випадкової колекції.
5. Перевір повноту метаданих кожного нового запису та відсутність нових порожніх translation queues.

## Пакування і середовища

Наведені вище старі кроки з ручним заповненням черг не застосовуються до raster-пачок: для них діє автоматичний DeepL-крок, описаний на початку цього розділу.

- Лише після окремого дозволу запусти `pnpm run media:prepare:images`, перевір підсумок, архів і пропуски через ліміт розміру. Команда повинна повторно використати готові оптимізовані файли, оновити метадані та доробити лише відсутні.
- Не додавай `--clean` для звичайного export або sync. Це окрема повна регенерація, дозволена лише після прямого запиту користувача саме на повторну оптимізацію всієї бібліотеки.
- Dev синхронізуй лише за прямим запитом і перевір фактичний результат через підтримувану адмін-поверхню.
- Stage і Production завжди потребують окремих нових підтверджень.
