# Iconify

## Локальний цикл колекції

1. Переконайся, що запитана колекція існує в установленому каталозі Iconify. Не встановлюй нові бібліотеки без окремого дозволу.
2. Після дозволу запусти `pnpm run iconify:pull -- --collection <slug>`.
3. Команда створює `library/iconify/<slug>/files`, `collection-meta.json`, `icons.json` і missing-черги назв, keys та синонімів.
4. Заповни черги за [правилами перекладу іконок](icon-translations.md), потім запусти `pnpm run translations:promote-missing`.
5. Застосуй значення лише до потрібної колекції: `pnpm run iconify:update-translations -- --collection <slug>`. Запуск без `--collection` оновлює всі колекції і дозволений лише за прямим запитом.
6. Перевір SVG, metadata колекції, `icons.json`, стабільні media keys та порожні опрацьовані missing-черги.

Числові токени не перекладаються й не з'являються у missing-чергах. Якщо джерело не містить додаткових metadata, порожні об'єкти є нормальними. Slug колекції є стабільним ідентифікатором; не змінюй його довільно.

## Пакування і сервер

- Підготовка архіву потребує окремого дозволу. Використовуй наявну команду `pnpm run media:prepare:icons`, якщо вона відповідає заданому обсягу, замість ручного архівування.
- Серверна синхронізація потребує окремого прямого запиту на конкретне середовище.
- Категорія з metadata колекції повинна вже існувати на цільовому сервері; не створюй або не змінюй серверні категорії без окремого запиту.
- Повторний імпорт того самого slug оновлює metadata і додає нові іконки без навмисного створення дубліката, але успіх усе одно перевіряй за фактичним результатом імпорту.
