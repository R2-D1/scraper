# Переклади зображень

## Область застосування

Для Unsplash і Pexels англомовні метадані беруться з джерела або локального sidecar JSON, а відсутні українські переклади name, alt і tags додаються через DeepL API. Не заповнюй українські поля або translation queues вручну: використовуй відповідний автоматичний процес. Якщо API недоступне, залиш пачку незавершеною й повідом про проблему.

Наведені нижче правила ручного заповнення черг стосуються інших джерел зображень, доки для них не налаштовано окремий API-процес.

## Назви

- Нормалізація назви є обов'язковим блокувальним етапом кожного імпорту зображень та ілюстрацій. Виконай її до запису в бібліотеку й повторно перевір перед канонічною підготовкою.
- ID постачальника, UUID, хеш, випадковий алфавітно-цифровий токен і назва на кшталт `Pexels photo 123` суворо заборонені у `name` та `alt`. Якщо джерело не дає змістовної назви, імпорт має завершитися помилкою, а не підставляти технічний ID.
- Однакові `name.en` і `name.uk` є сигналом для перевірки. Для технічного токена це безумовна помилка; сам збіг не є достатньою підставою відхиляти справжню назву бренду, моделі чи усталену абревіатуру.
- Англійську змістовну назву бери з опису або описової частини source slug без ID. Українська назва має бути перекладена до завершення імпорту.
- Черга: `translations/images/missing-name-translations/`.
- Дай цілісну природну українську назву, а не механічний переклад окремих токенів.
- Назва має стисло пояснювати, що на зображенні, і містити не більше десяти слів.
- Переглянь сам asset перед написанням назви. Англійська назва, опис і теги є лише контекстом, а не текстом для копіювання чи поелементної підстановки.
- Для пачки можна спочатку створити тимчасовий контактний лист із пронумерованими мініатюрами й візуально переглянути всю пачку. Це придатний спосіб первинно визначити зміст усіх asset без автоматичного перекладу.
- Якщо сюжет, напис, обʼєкт або колекція неоднозначні на контактному листі, відкрий конкретний asset окремо у повному розмірі перед перекладом. Не видавай контактний лист за детальну перевірку кожного файла.
- Якщо англійська назва крива або беззмістовна, створи точну пошуково корисну назву винятково за видимим вмістом.
- Результат має бути повністю українською. Латиниця допустима лише для справжньої назви бренду, моделі, твору або іншої власної назви; звичайні англійські слова, URL, хештеги, авторські описи, промпти й SEO-переліки заборонені.
- Не використовуй префікси на кшталт «Зображення:» або «Ілюстрація:», якщо тип медіа не є суттєвою частиною змісту.
- Записуй результат у відповідний queue-файл поточної пачки.

Перед просуванням черги перечитай кожну нову назву як редактор. Відхили запис, якщо він містить суміш мов, більше десяти слів, нереченнєвий список ключових слів, URL/соцмережу, рекламний або авторський текст чи не відповідає видимому asset. Не запускай просування, доки всі записи пачки не пройшли цю перевірку.

## Теги

- Черга: `translations/images/missing-tag-translations/`.
- Перекладай тег цілісною природною українською мовою з урахуванням зображення.
- Якщо тег незрозумілий, не описує реальний вміст або надмірно загальний, додай його до `translations/images/tag-blacklist.json`.
- Якщо значення треба прибрати і з tags, і з keys, додай його до `translations/images/tag-key-blacklist.json`. Перший blacklist стосується лише tags.
- Не перенасичуй metadata слабкими тегами.

## Застосування

1. Заповни лише нові записи поточної пачки у queue-файлах.
2. Виконай редакторську перевірку назв і семантичну перевірку тегів. Автоматична валідність JSON не є доказом якості перекладу.
3. Запусти `pnpm run images:promote-missing`: він лише переносить готові значення у майстер-словники й очищує черги; він не перекладає та не виправляє їх.
4. Запусти `pnpm run images:update-translations -- --slug <slug>` для кожного slug пачки.
5. Не запускай оновлення без `--slug`, якщо користувач прямо не просив оновити всю бібліотеку.
