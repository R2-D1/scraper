# Pexels: завантаження та підготовка фото

## Blacklist авторів

- Заборонені Pexels-фотографи зберігаються у `library/pexels-author-blacklist.json` як username профілю та/або точне ім'я автора.
- `pexels:pull-collections` відсіює такі фото до завантаження оригіналу.
- Після зміни blacklist запускай `pnpm run pexels:apply-author-blacklist`: команда видаляє вже імпортовані фото, ставить їхні media keys у список серверного видалення та прибирає їх із пов'язаних груп.
- Blacklist стосується Pexels-фото, не Pexels-відео.

## Завантаження

- Для API використовуй тільки свіжий `PEXELS_API_KEY`, налаштований у середовищі scraper. Не копіюй ключ у чат або до Divnex.
- Усі внутрішні призначення бери з актуального `library/collections.json`; Pexels-мапінги застосовуються тільки до внутрішньої image-колекції.
- Щоб завантажити всі фото з усіх налаштованих колекцій, виконай `pnpm run pexels:pull-collections`.
- Для малої пачки використовуй `pnpm run pexels:pull-collections -- --collection <slug> --limit-per-collection <n>`.
- Команда перед першим записом перевіряє доступ до всіх вибраних колекцій через офіційний API. Якщо ID недоступний, виправ повідомлену відповідність і повтори; не переходь до вебскрейпінгу.
- Фото зберігаються в `library/pexels/images/pexels-<id>/` разом з оригіналом і стандартним `media-meta.json`. До першого запису збери всі Pexels-мапінги для ID, щоб нове фото отримало їх разом.
- Якщо локальний оригінал фото вже існує, повністю пропусти запис: не перезаписуй файл, `media-meta.json`, колекції, теги чи статус. Оновлюй лише ID, для якого локального оригіналу ще немає.
- Нове фото має `taggingStatus: pending`. Не пакуй його, доки статус не стане `complete`.

## Візуальне тегування

Pexels API надає фото, розміри, URL, автора та alt-текст, але не надає теги або докладні метадані. Агент має відкрити кожне pending-фото у viewer або сам asset і визначити вміст саме візуально.

Для пачкового огляду:

1. Створи контактні аркуші з `pnpm run pexels:tagging:sheets`; за потреби обмеж одну внутрішню колекцію через `-- --collection <slug>`. Інструмент групує pending-фото за призначеною внутрішньою колекцією, додає slug під кожним thumbnail та створює поруч JSON-шаблони.
2. Переглянь кожне фото на аркуші окремо. Внутрішні колекції призначаються лише через `providerCollections` у `library/collections.json`; не додавай і не прибирай колекції під час тегування. Сумнівні кадри відкрий окремо у повному розмірі.
3. Ручна розмітка ведеться англійською: заповни в JSON англійську `nameEn` та 4–8 точних пошукових `tagsEn`; якщо доводиться вручну доповнювати назву чи alt, також пиши їх англійською. Не додавай `nameUk` або українські теги: відсутні українські переклади створить DeepL на наступному кроці. Не додавай припущень про невидимі об'єкти, слабкі асоціації чи зайві теги.
4. Застосуй кожну пачку командою `pnpm run pexels:tagging:apply -- --input <batch.json>`; спершу можна перевірити її без запису через `--dry-run`. Команда перевіряє IDs, початкову колекцію фото, формат і blacklist, зберігає англійські теги й додає до черги лише унікальні терміни, яких ще немає у майстер-словнику. Тегувальна пачка не може змінювати призначення колекцій.
5. Після застосування всіх пачок виконай `pnpm run images:update-translations -- --source pexels --pending-only --translate-missing`. Перекладний крок спершу використовує наявні словники, а в DeepL надсилає лише унікальні відсутні українські переклади назв, alt і тегів. Він додає переклади назв і тегів до майстер-словників, оновлює метадані й виставляє `taggingStatus: complete` після заповнення перекладів. Для API потрібен локальний `DEEPL_API_KEY` у `.env` з плану DeepL API Developer.

## Підготовка

- Переконайся, що кожне фото має `taggingStatus: complete`, двомовні теги, валідну image-категорію та принаймні одну наявну внутрішню колекцію.
- Запусти звичайну підготовку збереженням готових файлів: `pnpm run media:prepare:images --keep`.
- Для малої вибірки передай повторюваний `--slug` і окремий `--out`, наприклад `pnpm run media:prepare:images -- --out tmp/pexels-smoke/images --keep --slug pexels-8799441 --slug pexels-8799442`.
- Перевір підготовлений `tmp/images.zip` і `tmp/images/<slug>/media-meta.json`. Статус тегування й Pexels-мапінги належать внутрішнім даним scraper і не мають потрапити в архів.
- Цей процес завершується локальною підготовкою. Він не запускає синхронізацію в жодне середовище Divnex.
