# Спільні правила медіабібліотеки

## Джерело правди

- Інструкції та критерії рішень живуть у цьому скілі.
- Живі дані залишаються в проєкті: assets, метадані, intake, черги, майстер-словники та `library/collections.json`.
- Для Unsplash blacklist авторів є окремим правилом intake: заблоковані профілі не імпортуються, а вже наявні записи очищуються спеціальною командою.
- Не дублюй перелік колекцій у документації або скілі. Завжди читай актуальний реєстр.

## Колекції

- Колекції не прив'язані до джерела: Unsplash, власні зображення та інші потоки використовують один реєстр.
- Перед будь-яким призначенням або переглядом колекцій прочитай [описи колекцій](collection-descriptions.md). Спочатку звір кандидатні slug з актуальним реєстром, потім прочитай описи всіх реальних кандидатів і лише після цього приймай рішення. Довідник пояснює семантику, але не замінює живий реєстр і не дозволяє використовувати відсутню колекцію.
- Кожне зображення категорії `images` мусить мати щонайменше одну наявну колекцію відповідної категорії.
- Класифікуй за фактичним вмістом asset, а не за slug, filename, окремими тегами чи збігом ключових слів. Перед призначенням переглянь кожне зображення; для пачки можна використати contact sheet, але рішення все одно приймай по кожному asset окремо.
- Спочатку визнач, що користувач шукатиме на цьому зображенні: головний сюжет або практично корисний тип фону. Стиль, матеріал, освітлення, оточення та другорядні предмети не повинні витісняти головний сюжет.
- Завжди обирай основну колекцію. Додаткову додавай лише тоді, коли вона так само прямо описує помітний сюжет, об'єкт, середовище або практичне використання.
- Не додавай колекцію через слабку асоціацію, другорядну деталь або простий збіг тега. Якщо сумніваєшся — переглянь зображення; якщо додаткова колекція все одно сумнівна, не додавай її.
- Не використовуй широку колекцію `objects` як запасний варіант. Вона підходить для ізольованого предмета або предметного натюрморту лише тоді, коли немає точнішої наявної тематичної колекції.
- Не створюй нові колекції без прямого запиту користувача.
- Якщо жодна наявна колекція прямо не підходить, не призначай «найближчу» і не змінюй реєстр. Залиш asset невирішеним, зупини пакування цієї пачки та повідом, якої тематичної колекції бракує. Вимога мати колекцію не дозволяє вигадувати відповідність.
- Не використовуй regex, словники ключових слів або інші масові евристики для семантичного розподілу. Скрипт може лише записати вже прийняті поштучні рішення.

### Критичні межі

- `people` — фотографії реальних людей або реальних частин тіла, коли людина є помітним сюжетом. Не додавай сюди CGI-персонажів, статуї, манекени, іграшки чи абстрактні гуманоїдні форми. Стилізоване світло, маска або силует не виключають реальну людину, якщо це все одно фотографія людини.
- `architecture` — будівля, споруда, впізнаваний архітектурний елемент або сформований простір є головним сюжетом. Автомобіль біля будівлі, градієнтна сфера або макро матеріалу стіни самі по собі не є архітектурою.
- `gradients` — сам градієнт має бути головним вмістом і придатним як фон. Градієнтне освітлення чи фон позаду автомобіля, об'ємної форми або іншого виразного об'єкта не робить зображення градієнтом.
- `interiors` — кімната, робочий простір або інтер'єрна композиція є головним сюжетом. Ізольовані меблі, рослина, клавіатура, батарейка чи інший предмет не стають інтер'єром лише через домашній контекст.
- Стильова колекція на кшталт `abstract`, `patterns` або `textures` описує справді домінантну візуальну форму. Вона не замінює тематичну колекцію автоматично, але й тематична колекція не додається лише через зображений у рендері об'єкт.

### Контроль пачки

- Після поштучних рішень згенеруй contact sheet для кожної зміненої колекції та перевір її як цілісну видачу. Кількість записів і валідні slug не доводять семантичну правильність.
- Сумнівний thumbnail відкрий у повному розмірі. Якщо головний сюжет неможливо впевнено назвати за самим зображенням, не домислюй його зі slug або тегів.

## Переклади

- Заповнюй лише записи, що стосуються поточної пачки або прямо заданого обсягу.
- Для ручної розмітки Pexels-фото створюй англомовні назви й теги за видимим вмістом. Відсутні українські переклади отримуй через налаштований DeepL API за процедурою з [Pexels](pexels.md); спершу використовуй наявні майстер-словники й надсилай API лише унікальні відсутні значення.
- Не пиши українські переклади Pexels вручну й не позначай їх готовими, якщо API недоступне або повернуло помилку: залиш пачку незавершеною та повідом про проблему.
- Для інших джерел і для Iconify дотримуйся їхніх окремих інструкцій; правило DeepL для Pexels не поширюється на них автоматично.
- Не генеруй переклади підстановкою токенів, частковим перекладом slug/filename, словником відповідностей або іншою механічною трансформацією.
- Велика черга не послаблює вимоги якості. Працюй невеликими перевіреними пачками; якщо весь обсяг неможливо якісно опрацювати за поточний цикл, заверши лише перевірену пачку й прозоро повідом залишок.
- Missing-черга є робочим входом, а не помилкою і не завданням для користувача.
- Після заповнення черги застосуй відповідну команду просування у майстер-словники, потім онови лише поточні записи. Масове оновлення всієї бібліотеки запускай лише за прямим запитом.

## Перевірка

- Перевір кількість вхідних і прийнятих assets, дублікати та повноту метаданих.
- Для зображень перевір локалізовані name, alt, tags і keys, категорію, колекції, source, author, license та стабільний media key.
- Для іконок перевір колекційні метадані, SVG, локалізовані назви, keys, синоніми та стабільні media keys.
- Автоматизована перевірка не є ручним QA користувача.
