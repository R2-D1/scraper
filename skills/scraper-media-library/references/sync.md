# Синхронізація медіа з Divnex

## Джерело стану

- Відстежуваний Git реєстр `media-sync-state.json` у корені scraper зберігає останні підтверджені версії файлу й метаданих окремо для Dev, Stage і Production. Відсутній запис або hash означає, що відповідна версія не підтверджена.
- План для кожного середовища порівнює поточні підготовлені assets із цим реєстром. Нові медіа з усіх підтримуваних джерел потрапляють у план автоматично після появи в бібліотеці. Не визначай обсяг через Git diff, попередній коміт або серверний inventory під час звичайного запуску.
- Реєстр було початково звірено з усіма трьома середовищами. `--bootstrap` потрібен лише для середовища без початкового стану; він читає серверний inventory і локальні checkpoints, а непідтверджене залишає несинхронізованим. Не перезаписуй початковий стан повторним bootstrap.

## Порядок роботи

1. Прочитай спільні правила дозволів. Dev, Stage і Production потребують окремого прямого дозволу на серверний запуск.
2. Перевір ціль і запусти план без `--send`: `pnpm run media:sync:images -- --target dev|stage|prod --divnex-project <path-to-divnex2>`. Команда готує локальні assets і пакети, але не виконує серверний імпорт.
3. Для дозволеного середовища запусти ту саму команду з `--send`. Дочекайся результатів усіх пакетів і reindex. Не вважай передачу архіву або постановку в чергу успіхом.
4. Після підтвердженого успіху пакета скрипт атомарно оновлює лише відповідне середовище у реєстрі. Невдалий пакет або незавершений reindex не вважай повною синхронізацією. Повтори запуск для відновлення: збережений checkpoint, план і серверний результат пакета запобігають втраті підтвердженого прогресу.
5. Видалення відстежуються окремо для кожного середовища і вважаються завершеними лише після його серверного підтвердження.

Для відповіді про стан звіряй реєстр, незавершені checkpoints і сухий план відповідного середовища. Окремо називай уже підтверджені версії та те, що ще очікує синхронізації. Фактичний серверний стан міг змінитися поза scraper; inventory використовуй лише для цільової read-only діагностики, а не як звичайний механізм вибору пакетів.
