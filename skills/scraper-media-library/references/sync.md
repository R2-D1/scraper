# Синхронізація медіа з Divnex

## Джерело стану

- Відстежуваний Git реєстр `media-sync-state.json` у корені scraper є чергою лише тих медіа, для яких лишилася робота. Запис містить media key та середовища, де очікують файл, метадані або видалення. Коли всі три середовища підтвердили потрібні операції, запис видаляється.
- Кожен підтримуваний імпорт і редактор Media Viewer позначає змінені медіа одразу після локального запису. Заміна файла також змушує підготувати саме цей asset заново. План синхронізації бере лише записи черги; Git diff, попередній коміт і серверний inventory не визначають його обсяг.
- Поточну чергу перенесено з одноразової звірки Dev, Stage і Production. Незавершені пакети Stage лишаються в черзі. Серверний inventory використовуй лише для цільової read-only діагностики.

## Порядок роботи

1. Прочитай спільні правила дозволів. Dev, Stage і Production потребують окремого прямого дозволу на серверний запуск.
2. Перевір ціль і запусти план без `--send`: `pnpm run media:sync:images -- --target dev|stage|prod --divnex-project <path-to-divnex2>`. Команда готує локальні assets і пакети, але не виконує серверний імпорт.
3. Для дозволеного середовища запусти ту саму команду з `--send`. Дочекайся результатів усіх пакетів і reindex. Не вважай передачу архіву або постановку в чергу успіхом.
4. Після підтвердженого успіху пакета скрипт атомарно закриває лише відповідне середовище в черзі. Якщо медіа було знову відредаговано під час імпорту, старий пакет не закриває його новий запис. Невдалий пакет або незавершений reindex не вважай повною синхронізацією. Повтори запуск для відновлення: збережений checkpoint, план і серверний результат пакета запобігають втраті підтвердженого прогресу.
5. Видалення відстежуються окремо для кожного середовища і вважаються завершеними лише після його серверного підтвердження.

Для відповіді про стан звіряй чергу, незавершені checkpoints і сухий план відповідного середовища. Фактичний серверний стан міг змінитися поза scraper; inventory використовуй лише для цільової read-only діагностики.
