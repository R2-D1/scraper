# Lummi

## Джерело intake

- Userscript `tools/lummi-favorites-downloader.js` працює на `lummi.ai`: клік по ще не вибраному сердечку фото, ілюстрації чи 3D-зображення в сітці або у відкритому detail/modal отримує metadata через Lummi API і завантажує лише `<slug>-lummi.json`. Для картки slug і тип беруться з її `/photo/`, `/illustration/` або `/3d/` посилання, а для головного сердечка detail/modal — з поточного URL. `sourceUrl` у sidecar зберігає фактичний тип маршруту; всі три типи імпортуються в спільну категорію `images`.
- Зміна файла в репозиторії не оновлює вже встановлений userscript у Tampermonkey. Після зміни користувач має замінити його код у Tampermonkey та зберегти.
- Вхідна тека — `intake/lummi/`; вона не версіонується. Клади туди лише JSON, зображення поруч не потрібне.
- Перед імпортом команда перевіряє валідність JSON, наявність `id`, `slug`, `name`, `url`, автора, ліцензії й тегів. Sidecar-и з asset URL поза HTTPS `assets.lummi.ai` (зокрема випадкові `/api/pro/image/` URL) одразу видаляються з intake з попередженням і не блокують решту пачки.

## Локальний імпорт

Запускай тільки канонічну команду:

`pnpm run lummi:import-intake`

Команда:

1. Читає `url` із JSON і приймає лише HTTPS asset на `assets.lummi.ai`.
2. Завантажує raster, перевіряє MIME та фактичні розміри через Sharp.
3. Зберігає asset у `library/lummi/images/<slug>/`, створює `media-meta.json` із джерелом, автором, ліцензією, описом і тегами.
4. Автоматично перекладає відсутні українські name, alt і tags через налаштований DeepL та завершує локалізацію запису.
5. На першому імпорті залишає `collectionSlugs` порожнім. Не призначай колекції за slug або тегами: переглянь asset у viewer і застосуй спільні правила класифікації.
6. Згортає однакові slug усередині intake й завантажує asset лише один раз. Якщо slug уже має `taggingStatus: complete` та растровий файл, повторний asset пропускається. Відповідні JSON видаляються лише після успіху завантажень і перекладів нових записів; при помилці intake зберігає JSON для безпечного повтору, а часткові записи мають `taggingStatus: pending` і не повинні пакуватися.

Повторний імпорт того самого slug зберігає `mediaKey`, pinned і вже призначені колекції. Якщо в бібліотеці лежить asset з іншим розширенням, імпорт зупиняється замість створення двох основних файлів.

## Перевірка результату

- Кількість нових каталогів бібліотеки має відповідати прийнятій пачці, а intake після повного успіху не повинен містити її JSON.
- У кожному каталозі має бути рівно один raster і `media-meta.json`; metadata dimensions мають дорівнювати фактичним розмірам файла.
- Перевір `sourceName: Lummi`, автора, ліцензію, стабільний media key, `taggingStatus: complete`, локалізовані name, alt і tags та відсутність записів пачки у missing queues.
- До пакування кожен asset мусить отримати щонайменше одну реальну колекцію через візуальний перегляд.
- Імпорт не дозволяє автоматично запускати `media:prepare:images` або синхронізацію Dev, Stage чи Production.
